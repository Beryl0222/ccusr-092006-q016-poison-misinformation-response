# 中毒误导信息响应

区域疾控中心的误导信息与暴露响应后端。面对雨后高发的毒蘑菇咨询，系统把公众提交、误导说法研判与事件分诊分开管理：它不替医生确认物种，而是依据可观察症状、群体暴露和当时有效指引给出行动级别（联系急救 / 立即就医 / 持续留观）。

## 运行

```bash
npm test        # 领域约定 + 后端规则测试
npm start       # 启动 HTTP 服务（默认 8080，PORT 可改）
```

## 领域规则

- **六类提交事实分开保存**：说法目击（含来源链接）、蘑菇样本线索、食用时间、同餐关系、症状时间线各有独立集合，互不混放。
- **不确认物种**：样本线索只允许记录公众自称的识别结果（如"AI识别可食"）作为未证实线索；写入 `confirmed_species` 会被拒绝。每次评估都附带 `species_note` 声明。
- **重复来电合并**：共享联系人指纹或餐次指纹（食用日期+地点）的提交并入同一未结案事件；已结案事件不再吸收新来电。
- **症状暂缓不能结案**：`relieved` 只记录不结案。结案必须同时满足"末次症状后观察期"与"末次食用后迟发窗口"（警惕假愈期），提前结案返回 409 与最早可结案时间。
- **说法研判带版本**：专家判断必须附证据与适用范围，版本递增，最新判断决定说法状态；平台与社区的更正结果回传留痕。
- **指引版本化**：每次评估引用当时有效的指引版本，历史评估不改写。新指引发布后，未结案个案自动进入重评队列，处理重评时按新指引重新分诊。
- **升级可溯源**：行动级别上调时记录触发源、指引版本与促成升级的公开信息，值班人员可经溯源接口还原因果链。

## 目录

- `src/poison_misinformation_response.js`：事件种类与最小字段校验（领域约定）。
- `src/store.js`：内存集合 + 追加式事件日志。
- `src/submissions.js`：六类事实的校验、拆分与合并指纹。
- `src/triage.js`：分诊引擎与结案观察窗（纯函数）。
- `src/incidents.js`：事件开立/合并/评估/升级/结案与溯源。
- `src/claims.js`：说法登记、专家研判、更正回传。
- `src/guidelines.js`：指引版本与"当时有效"解析。
- `src/service.js`：用例编排（含重评队列）。
- `src/server.js`：无依赖 `node:http` JSON API。
- `src/seed.js`：演示用初始指引。
- `data/sample.json`：用于核对资料格式的虚构事件。

## API 一览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/submissions` | 接收公众提交，自动合并并分诊 |
| POST | `/claims` | 登记误导说法（含来源链接） |
| GET | `/claims/:id` | 说法详情（研判版本、更正记录） |
| POST | `/claims/:id/reviews` | 追加专家判断（证据+适用范围+版本） |
| POST | `/claims/:id/corrections` | 平台/社区更正回传 |
| GET | `/claims/:id/impact` | 该说法促成升级的事件列表 |
| POST | `/guidelines` | 发布新指引版本，未结案个案自动进重评队列 |
| GET | `/guidelines/current` | 当前生效指引 |
| GET | `/reevaluation-queue` | 待处理重评任务 |
| POST | `/reevaluation-queue/:id/process` | 处理重评（按新指引重新分诊） |
| GET | `/incidents/:id` | 事件详情与六类事实 |
| GET | `/incidents/:id/trace` | 值班溯源：评估、升级与促成说法 |
| POST | `/incidents/:id/close` | 结案（观察窗校验，提前则 409） |

所有响应统一为 `{ ok, ... }`；校验失败返回 400 与 `problems` 列表。
